Boat Tracker Android App

GPS race tracking for sailing events.

Boat Tracker is an Android application that starts from a boattracker: deep link, receives event configuration from your backend, and periodically posts the boat's GPS position while tracking is enabled.

What It Does

The app is designed for race organizers who need live boat positions during an event without building a custom mobile app for every race.

Deep-link startup Event selection Background tracking Organizer messages HU / EN UI

Participants open a link from email, chat, or a web page. The app resolves configuration, displays the selected boat and event, then sends GPS coordinates to the configured backend endpoint.

Main Screen

User Flow

Open the tracker

The user taps a boattracker: link, usually sent by the organizer. If launched directly, the app fetches startup events and asks the user to choose one.

Allow location

The app requests Android location permissions so it can include coordinates in every tracking request.

Broadcast position

Tracking starts enabled by default. The user can stop broadcasting with the switch; the app clearly warns that organizers cannot see the boat.

Deep Links

Use a custom-scheme URL where everything after boattracker: is the backend initialization URL.

boattracker:https://fenyveskupa.hu/api/pozicio/init?hajo=pentike-teszt&nevezesId=68b1f653221a01cf65c552b3

For Android emulator testing against a server running on the host machine, use 10.0.2.2.

boattracker:http://10.0.2.2:3000/api/pozicio/init?hajo=pentike-teszt&nevezesId=test

Backend Contract

GETStartup Events

Used when the app is opened directly instead of through a deep link.

GET https://fenyveskupa.hu/boattracker/startup
{
  "events": [
    {
      "name": "3. Késő Pál Fenyves Kupa",
      "start": "2026-08-30",
      "configUrl": "https://fenyveskupa.hu/api/pozicio/init"
    }
  ]
}

GETEvent Configuration

Called first when the app starts from a deep link or after the user selects an event.

GET https://fenyveskupa.hu/api/pozicio/init?hajo=pentike-teszt&nevezesId=test
{
  "logo": "https://fenyveskupa.hu/verseny/logo.png",
  "event": "3. Késő Pál Fenyves Kupa",
  "motto": "A szél legyen velünk",
  "url": "https://fenyveskupa.hu/verseny/.../pozicio/hajok"
}

POSTCoordinate Updates

The app posts the current GPS position to the url from the event configuration response.

{
  "n": "pentike-teszt",
  "id": "68b1f653221a01cf65c552b3",
  "la": 34.234234,
  "lo": 34.232343
}

Tracking Response

The backend controls the next broadcast interval and may send a message to display in the app.

{
  "f": 30,
  "msg": "Message to be displayed on screen"
}

f is the broadcast frequency in seconds. An empty msg means no new organizer message.

Integration Checklist

1. Create participant links

Generate a unique deep link per boat or registration. Include the ship name and registration ID as query parameters on your initialization URL.

2. Return configuration

Your init endpoint should return event metadata, an optional logo URL, and the coordinate POST endpoint.

3. Store positions

Accept JSON POST bodies with ship name, registration ID, latitude, and longitude. Store them with server timestamps for race tracking.

4. Control frequency

Return f to tune traffic and battery usage. A value such as 30 sends one update every 30 seconds.

5. Send race messages

Return msg when the race office needs to notify boats. New messages appear at the top and are kept in the message list for the session.

6. Handle failures

If requests fail, the app displays a communication error. Your backend should return valid JSON for every successful tracking request.

Test Server

The repository includes a small Node.js server that serves startup configuration, event initialization, a test page with a deep link, and coordinate POST responses.

node server/server.js

Optional environment variables:

PORT=3000 FREQUENCY=10 MESSAGE="Race office message" node server/server.js

Open the test page on the Android emulator and tap the generated deep link:

http://10.0.2.2:3000/

App Behavior

Tracking lifecycle

  • The first coordinate POST includes GPS coordinates.
  • The app continues broadcasting in the background while enabled.
  • Broadcasting stops when the user turns it off or force-closes the app.
  • The last broadcast time is shown without the date.

Messages and rules

  • Backend messages appear in a dismissible top message box.
  • New messages are added to the message list with newest first.
  • Important sailboat racing rules are shown before the message list.
  • Tapping a rule opens a detail screen with the image and description.

Production Notes

Use HTTPS in production

The test server and emulator examples use plain HTTP for local development. Public event integrations should use HTTPS endpoints and should validate boat identifiers on the backend.

Logo

Return a public image URL in logo if each event has its own branding. The app falls back to its built-in competition logo when loading fails.

Privacy

The app tells users their position is sent to organizers for event tracking. Store positions only for the event window unless your privacy policy says otherwise.

Localization

The app includes English and Hungarian strings and lets the user switch language from the main screen before the server line.
